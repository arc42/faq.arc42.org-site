{%- comment -%} Self-contained search widget: markup + the script that drives it. Drop it anywhere with a one-line `{% include search.html %}` — it assumes nothing about its surroundings beyond being inside . The dropdown is positioned against `.faq-search`, which owns its own `position: relative`, so it does not need a positioned ancestor supplied by the host markup. WP-B's masthead can host it in the marked search slot; until then it lives in the aside rail. Only the include line moves — nothing here changes. Markup contract with assets/js/search.js (do not restructure): [data-faq-search] the root, carries data-baseurl form.faq-search__form submits to /search/?q=… when JS is absent input#search[name=q] role=combobox, the only search input kbd[data-faq-search-hint] platform-aware ⌘K / / hint, filled by JS #faq-search-panel role=listbox, filled by JS [data-faq-search-status] aria-live result count The results page contributes #search-page-results; the same script fills it. The script tag ships with the include so the widget stays droppable. It is `defer`, so the DOM is complete when it runs, and the script no-ops if it is ever evaluated twice. {%- endcomment -%}
